# ABI 2 request sessions

Status: accepted and verified for #13 on the scoped simulator/emulator matrix below.

The generated Rust artifact owns a shared executor with two workers. Each busy direct client and embedded document owns a session. Native modules track their clients' sessions and close them on runtime teardown. Hosts submit work, cancel requests and drain completed results using ordinary public native-module or WebView APIs. This keeps execution and cancellation semantics identical across RN and Lynx without introducing a Tauri application event loop or producer-facing APIs.

Hosts check for results every 16 ms while requests are pending, then stop polling. Polling adds a delivery delay, normally one interval or less while the runtime is active, and a small native-call overhead while busy. It avoids retaining JavaScript callbacks in Rust and works with the public primitive types supported by the current Lynx platform-module code generator.

ABI 2 adds `session_create`, `session_start`, `session_poll`, `session_cancel` and `session_destroy` symbols under the `tauri_native_` prefix. Start copies its UTF-8 inputs and returns immediately with acceptance or a transport error. Poll drains an array of `{id, response}` entries, where `response` is the ordinary ABI 2 JSON envelope. Every non-null string uses the existing matching free function. Existing Tauri command names, serde inputs/outputs and Result success/rejection remain intact. Supported root async functions are awaited on a tool-owned Tokio runtime with two scheduler threads; runtime/state/plugin-dependent producer APIs retain their existing restrictions. Tokio is configured only in the disposable manifest, preserving any existing dependency specification and adding the needed runtime/I/O features. The generated dependency defaults to 1.53.1 when the producer has none. No Tauri runtime dependency is linked into the artifact.

The global queue accepts at most 64 waiting jobs. Each session retains at most 64 requests, including completed results awaiting collection. Excess work fails with `queue_full`; duplicate pending IDs fail with `duplicate_request`. Closing a session removes it from the registry, removes its queued jobs and discards its pending results. A new session receives a fresh identity. Every accepted request also has an internal generation, so cancellation and reuse of a request ID cannot redirect an older completion.

Cancellation removes queued work and suppresses delivery of work already claimed by a worker. It does not preempt Rust code, undo side effects or promise a completion deadline. A running function can finish after cancellation or session destruction. Its result is discarded unless its exact request generation is still pending. Completion and cancellation settle each host Promise at most once. An indefinitely blocked command can occupy one of the two workers until the process exits.

The host `invoke` API becomes Promise-based and accepts an optional host-owned AbortSignal. Its returned Promise has `cancel()`, so cancellation does not require an AbortController polyfill in Lynx. The previous blocking API moves to explicit `invokeSync` for migration, including legacy ABI 0 and ABI 1 artifacts. Nonblocking invocation requires ABI 2 and diagnoses older artifacts; rebuilding with the CLI is the migration path. Ordinary producer frontend `@tauri-apps/api/core.invoke` remains a Promise and needs no new import. Frontend cancellation follows document/view teardown. A fresh document has a distinct identity, and native delivery plus the injected client ignore responses for retired documents. Remount loads a fresh frontend; Android also injects the bridge into bundled HTML served on reload.

Verification must cover out-of-order completion, running and queued cancellation, reused IDs, queue saturation, source integrity, async Tauri parity, UI interaction during delayed Rust work and teardown/remount/reload on every host/platform. Rust protocol tests alone do not certify host lifecycle integration.

Evidence (2026-09-07): Rust protocol, shared client, package and type checks pass (CLI 32, RN 9 and Lynx 2 tests). The async export gate compares real Tauri async IPC with both Objective-C++ session bridges, runs ordinary frontend build hooks, verifies source/frontend integrity, exports all mobile slices and deletes the producer. The macOS compatibility/stress and portable iOS/Android artifact gates also pass with ABI 2. All thirteen remaining negative compatibility fixtures compile as ordinary Tauri applications, then fail export with the expected diagnostics and unchanged authored files.

All four copied-artifact Release lifecycle flows pass: RN iOS/Android 52/52 seconds and Lynx iOS/Android 51/49 seconds. They cover UI interaction, cancellation, remount, page reload and a public native runtime replacement while old Rust work remains alive. The hosts build with neither Cargo nor rustc on PATH. Separate ABI 0 calculator regression flows pass on all four combinations through `invokeSync` and the legacy WebView path. Both Android APKs pass 16 KB alignment checks. These are arm64 simulator/emulator runs, not physical-device or external-adoption evidence.

R8 preserves all six JNI method names and the annotated WebView `postMessage` entry point in both actual compiled SDK bridges. Full Lynx example minification was also attempted, but optional XElement/Fresco/Gson/ServalMarkdown dependencies are absent in that host. It is not recorded as a passed full-app shrinker gate; #19 tracks that separate integration check. The normal Release hosts pass their native flows.

Local reports are in `target/async-protocol/export-report.json`, `host-report.json`, the four `*-lifecycle-*.xml` and four `*-legacy-*.xml` files, and `r8/report.json`. See [the reproducible gate](../testing-async.md).
