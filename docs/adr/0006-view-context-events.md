# Local view context and scoped standard events

Status: verified on 2026-09-07 for #15. All four view/event flows and all four async lifetime regression flows passed.

Each embedded view owns a document generation. Local path/query/fragment context belongs to its packaged origin; the host receives load-start, ready and load-error callbacks. Changing the local path retires the previous document. Readiness means the main document and injected bridge have loaded, not that application data or every resource has finished loading.

The event proof uses the pinned ordinary `@tauri-apps/api/event` package. Supported calls must explicitly select `{ kind: 'Webview', label: 'main' }`: `listen`, `once`, `emitTo` and the returned unlisten function. These notifications are confined to one embedded document, including its host event callback. Native host views are independent scopes; there is no cross-view routing.

Default/global `listen` and `emit`, other labels, window/app targets, system events and Rust AppHandle emission remain unsupported and must fail explicitly. Converting Tauri's default all-target behavior into local-only delivery would silently change the API. The verified event-name subset is ASCII alphanumeric plus `/`, `:`, `_` and `-`; system names starting with `tauri://` are not emitted by the host. This is a scoped compatibility extension, not general event/plugin/window support. The producer uses standard Tauri APIs and ordinary URL parsing, with no tauri-native frontend dependency.

Payloads use JSON serialization; omitted payload becomes null. Event delivery is asynchronous, and listener IDs identify subscriptions. Emission acknowledgement does not promise that handlers have completed. No ordering among different listeners is promised. Each document retains at most 64 callback registrations. Unlisten, once and document teardown release callbacks; delivery carries the document generation so a retired document cannot receive new host messages or redirect old messages to a replacement. Host-to-view notifications are sent only to a ready current document and are not replayed across navigation.

The proof launches a real ordinary Tauri 2.11.5 desktop frontend with API 2.11.1, then exports the unchanged frontend and deletes the producer. RN 0.86.3 and Lynx 4.0.1 Release hosts pass the two-view flow on iOS Simulator 26.4.1 and Android API 37 with 16 KB pages. The four flows verify ready/error/context, scoped messages, duplicate suppression, unlisten, navigation, reload and remount. Both Android APKs pass 16 KB ZIP alignment. Host builds use the packed SDK and copied artifacts with no Rust tools on PATH.

The VM gate additionally loads the actual pinned event/core JavaScript modules against all four injected shims and verifies unsupported targets, callback limits and retired-document delivery. Its results alone do not establish native lifecycle parity. The ordinary desktop fixture grants `core:event:default` to `main`; preserving that configuration does not imply an embedded Tauri ACL engine. See [Tauri's event API](https://v2.tauri.app/reference/javascript/api/namespaceevent/) for broader target semantics and [the reproducible gates](../testing-views.md) for evidence locations. No physical-device execution or independent external adoption is claimed.
