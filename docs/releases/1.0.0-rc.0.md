# 1.0.0-rc.0 candidate

This is an experimental, reviewable candidate for the source-preserving workflow. It is not a stable 1.0 release or a statement that adoption and physical-device acceptance have completed. Source versions and prepared tarballs do not establish npm publication.

## Included behavior

- Install the CLI in an ordinary Tauri project, inspect its registered commands and export portable iOS/Android binaries, frontend assets and generated TypeScript contracts.
- Consume copied artifacts through React Native, Expo CNG or Lynx, without producer source or Rust tools in the native host build.
- Use ABI 2 nonblocking invocation and explicit cancellation/document/runtime lifetime semantics, with scoped frontend interactions and the verified application-data-directory adaptation.
- Diagnose compatibility and artifact problems, refresh exports incrementally, and watch ordinary source changes.

The [compatibility contract](../compatibility.md) defines supported signatures/APIs and explicit exclusions. The [Fieldnotes walkthrough](../examples/fieldnotes.md) and [migration guide](../migration.md) show the actual installation and host APIs. The producer keeps its ordinary desktop frontend and Rust source.

## Distribution and the stable gate

Changesets prerelease mode prepares the `rc` version suffix. The packages retain `publishConfig.tag: experimental`, and the existing release workflow can publish only the tarballs certified by its required validation jobs. Until a successful publication is recorded, use the matching tarballs from the candidate workflow artifact.

Keep [the adoption records](../adoption.md) open until two independent projects and physical RC checks have evidence. A failed walkthrough returns to the responsible roadmap issue. Exiting prerelease mode and promoting the npm channel require a reviewed release change after those gates and maintainer authorization. No evaluator names, private projects or test results are fabricated or published without consent.
